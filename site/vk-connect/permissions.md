# Доступ к сообществам и текстовым публикациям VK

Приложение Content Planner: **54867924**.
Redirect: `https://vichepaev22.github.io/content-planner-demo/vk-connect/`.

Вход VK ID подтверждает личность. Разрешения `groups` и `wall` проверяются
отдельно. Пилот позволяет явно проверить чтение groups.get; наличие флага
scope не заменяет фактический ответ VK. Записи отправляются только после
предпросмотра и отдельного нажатия владельца.

Актуальная документация `wall.post` указывает пользовательский ключ,
полученный в Standalone-приложении через Implicit Flow, и отдельно
согласуемое право `wall`. Обычный вход нового VK ID приложения не гарантирует
совместимость. Если VK не предоставляет `wall`, нельзя исправить это одной
галочкой в нашем интерфейсе или чужим ID приложения.

## Черновик запроса в поддержку VK

Адрес из официальной документации: `devsupport@corp.vk.com`.
Это подготовленный текст; приложение не отправляет письма.

> Здравствуйте! Для собственного приложения Content Planner, ID 54867924,
> нужен личный пилот владельца сообщества: просмотр его сообществ через
> groups.get и публикация текстовых записей от имени выбранного сообщества
> через wall.post. Также нужна нативная отложка с параметром publish_date.
> Вход реализован через VK ID с PKCE. Прошу уточнить, какой допустимый тип
> приложения, способ получения пользовательского ключа и согласование groups/wall
> нужны для этого сценария, учитывая условия текущей документации wall.post.
> Название и ID принадлежащего мне тестового сообщества: [заполнить].
> Публикации выполняет сам администратор после предпросмотра; доступ к личным
> сообщениям, друзьям, рекламе и платёжным данным не запрашивается.

Пароли, access/refresh tokens, защищённый/сервисный ключ и callback-коды
в письмо или чат не прикладывайте.

## Если запрос чтения не проходит в браузере

Ошибка сети/CORS не доказывает отсутствие самого права. В таком случае
нужен собственный серверный коннектор. Пилот не передаёт токен публичным
прокси и не называет такую ошибку успешным подключением.

## Проверка результата

Сначала выберите своё тестовое сообщество из реально полученного списка.
Для отправки требуется роль редактора или администратора и фактический `wall`.
Для теста можно подготовить текст и время на десять минут позже.
«VK принял отложенную запись» означает приём в отложенные; фактический выход
нужно отдельно проверить в VK в заданное время. При неизвестном результате
отправка автоматически не повторяется.

Источники, проверено 05.11.2026:

- [groups.get](https://dev.vk.com/ru/method/groups.get)
- [wall.post](https://dev.vk.com/ru/method/wall.post)
- [Права доступа](https://dev.vk.com/ru/reference/access-rights)


## Локальный коннектор

В рабочем проекте запустите `Start-Content-Planner.cmd` или `npm run local:vk`,
затем откройте http://localhost:4319/. Процесс слушает только 127.0.0.1:4319.
Вход проходит через собственное приложение VK ID и уже зарегистрированную
страницу GitHub Pages; она передаст одноразовый код фиксированному локальному
callback. PKCE verifier и токен остаются в памяти локального процесса.
Перезапуск процесса завершает сеансы. Новый callback в VK регистрировать не нужно.

Этот режим убирает браузерный транспорт из запросов API. Если VK отказывает
в groups/wall или нужном типе ключа, локальный процесс не обходит этот отказ.
Проверьте приложение и при необходимости согласуйте доступ с поддержкой VK.
