# Регистрация Content Planner в VK ID

Подготовлено 31.10.2026. Локальный модуль: `http://localhost`, порт 80.
Готовые файлы: `icon.png` (512 × 512), `icon.svg`, `fields.json` и
`technical-privacy.md`. Это комплект настройки, а не свидетельство регистрации
или одобрения приложения со стороны VK.

## 1. Кабинет и владелец

Откройте [кабинет VK ID](https://id.vk.com/about/business/).
По текущей документации вход разработчика выполняется через VK Бизнес ID.
Создайте свой профиль бизнеса и укажите собственные достоверные данные.
Конкретный набор подтверждений зависит от статуса владельца и формы VK.
Не нужно заранее публиковать готовый сайт или покупать подписку Onlypult.
Пароль VK вводится только на официальной странице VK.

Подтверждение профиля необходимо для полного управления настройками и ключами.
VK указывает срок 60 дней от создания первого приложения, после которого
неподтверждённые приложения блокируются. Для нашей проверки лучше завершить
подтверждение сразу. Не вводите вымышленные организацию, ИНН или адрес.

## 2. Карточка приложения

В разделе «Мои приложения» выберите «Добавить приложение».

| Поле | Значение |
| --- | --- |
| Название | Content Planner |
| Платформа | Web |
| Иконка | `icon.png` из этой папки |
| Базовый домен | `localhost` |
| Доверенный Redirect URL | `http://localhost` |
| Уровень конфиденциальности | Публичное |
| Описание, если запрошено | Локальный инструмент для просмотра сообществ владельца аккаунта ВКонтакте: групп, публичных страниц и событий. |

Точный адрес возврата важен. Код использует `http://localhost` без порта и без
пути. VK документирует локальную HTTP-проверку на порту 80; другие произвольные
локальные порты сейчас не поддерживаются. Старый макет на порту 4318 не является
адресом возврата этого модуля. HTTPS/443 возможен в VK, но в этот пилот не входит.

Приложение остаётся публичным клиентом с PKCE. Токен получает локальный процесс
на вашем компьютере; он не передаёт его в JavaScript страницы. Для
конфиденциального типа понадобятся другая конфигурация, IP сервера и service_token;
этот пилот их не принимает. Если VK требует другой тип — сначала нужно изменить
интеграцию, а не вставлять защищённый ключ в поле ID.

## 3. Доступы и документы

- Базовый доступ: `vkid.personal_info`. Модуль сохраняет в сеансе только ID
  пользователя, не запрашивает отдельные методы чтения профиля.
- Нужен доступ `groups` для чтения каталога через `groups.get` и `groups.getById`.
  Проверьте его наличие в своей карточке приложения. Запрошенный scope не
  гарантирует, что VK его предоставит. Если опции нет или метод запрещён,
  обратитесь в поддержку VK с обоснованием ниже. Один VK ID не гарантирует
  доступ к каталогу, и собственное приложение не получает привилегии Onlypult.
- Телефон, почта, друзья, сообщения, wall, offline, фотографии и видео в этой
  версии не запрашиваются.
- В разделе правовых документов VK предлагает собственные документы сервиса
  или типовые. Выберите доступный вариант лично, ознакомившись с текстом.
  Техническое описание `technical-privacy.md` подготовлено как основа; в нём
  намеренно нет выдуманных реквизитов владельца. Если потребуются публичные URL
  своих документов, сначала заполняются реквизиты и публикуются утверждённые
  тексты на вашем домене. Локальный адрес не заменяет публичный URL.

Черновик обращения в поддержку (не отправлен):

> Создаю Content Planner для личного локального использования владельцем
> аккаунта. Нужен доступ groups и вызов groups.get с extended=1, а также
> groups.getById, чтобы после добровольного входа пользователь видел свои
> сообщества и выбирал одно для просмотра. Приложение не запрашивает пароль,
> сообщения или друзей и не публикует записи. Токен хранится только в памяти
> локального процесса. Прошу сообщить, какой доступ и согласование необходимы
> для этого сценария в моём приложении. ID приложения: [вставить свой номер].

Адрес поддержки из документации VK: `devsupport@corp.vk.com`.
Не прикладывайте к обращению пароль, защищённые ключи, токены или callback-коды.

## 4. Подключение к локальному модулю

1. Запустите `Start-VK-Connect.cmd` из корня проекта. Требуется Node.js 24,
   дополнительные пакеты не нужны. Окно процесса должно оставаться открытым.
2. Откройте `http://localhost`. Сервис слушает только loopback 127.0.0.1.
3. Скопируйте в форму только числовой **ID приложения** из своей карточки VK.
   Он публичный. Защищённый и сервисный ключи не копируйте.
4. Сохраните ID, нажмите «Войти через VK ID». Проверьте официальный домен VK,
   ознакомьтесь с разрешениями и подтвердите вход самостоятельно.
5. После возврата проверьте группы/страницы/события. Найдите своё тестовое сообщество по названию.
6. Выберите её и откройте сведения. На стене ничего не изменится.
7. Нажмите «Завершить локальный сеанс» и проверьте, что список исчез.

Список загружается страницами по 1000, до пяти страниц за одно действие.
Если данных больше, интерфейс показывает неполноту и кнопку продолжения.
Фильтр управления отражает сведения VK, а не обещание права публикации.

## 5. Проверки и ограничения

`npm test` проверяет локальную логику на искусственном провайдере. Эти проверки
не доказывают, что VK одобрил приложение или вернул реальные группы.
Живую проверку можно завершить только после регистрации и разрешения groups.
Если VK не предоставляет этот доступ, модуль показывает ошибку, а не учебный
список. Токены, callback-коды и пароли нельзя присылать в чат.

Перезапуск удаляет сеансы и токены. Выход очищает локальный сеанс, но не отзывает
разрешение на стороне VK: это делается в настройках аккаунта VK. Публичный
client_id хранится в `.secrets/vk-connect-client.json`; его изменение завершает
все локальные сеансы этого модуля. Публикующего кода в нём нет.
